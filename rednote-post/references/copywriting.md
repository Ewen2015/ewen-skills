# 文案：标题与正文

小红书是**信息流**：读者在滑动中决定停不停。所以文案的任务不是"介绍这份内容"，
而是**在前两行让人认出"这说的是我"**。

## 标题

硬限制 **20 字**，超了 CLI 直接抛错。宁短勿长，13–17 字最好念。

有效的是**认知冲突**，不是概括：

| 套路 | 例 |
| --- | --- |
| 你懂的比你能说的多 | 为什么你懂的，永远比能说出来的多 |
| 反常识结论 | 越努力越没结果，因为你搞反了顺序 |
| 具体到能想象 | 我用 3 年才明白：说不清的本事最值钱 |
| 指名对象 + 好处 | 想做知识管理，先读这一本 |

**不要**用：震惊体、纯书名、"XX 读后感"、"分享一本好书"——这些没有信息量，
也不会让人想点开。

标题和封面图是同一句话的两半：**封面承担冲击力，标题承担信息**。两者不要重复措辞，
但必须指向同一个点（曾经出现过封面写"永远比说出来的多"、标题写"永远比能说出来的多"
这种不一致，是编辑事故，发布前一定要对齐）。

## 正文骨架

目标 **700–900 字**。低于 600 字读者觉得"没什么可收藏的"；超过 1000 字会被截断。

```
① 钩子（2–3 行）    一个读者正在经历的具体场景，不要抽象概括
② 概念（2–3 行）    给出名字 + 一句话定义 + 出处（页码/年份）
③ 事实底座（1–2 行）体量、结构、重心——让读者知道这是什么量级的东西
④ 可带走的点（主体）N 条，每条 = 一句观点 + 一句"所以你该怎么做"
⑤ 怎么用（2–3 行）  怎么读/怎么练/从哪开始，越具体越好
⑥ 顺藤摸瓜（2–4 行）相关作品，一句话说明关系
⑦ 收尾（1–2 行）    回到读者自己身上：这跟你有什么关系
⑧ 出处（1 行）      作者《书名》｜编者/译者｜版本
⑨ 标签（1 行）      #标签 #标签 ...
```

### ④ 是最重要的一段

读者点赞收藏的动机是"**我以后用得上**"。所以每条必须从内容里翻译成读者能用的一句话：

> ✗ 附带焦点：细节退到背景，整体才会浮现。
> ✓ 附带→焦点：用锤子时，手感在手上，注意力却钉在钉子上。细节必须退到背景，整体才会浮现。
>   → 别一边做一边解剖自己，先做进去。

用**具体的物**（锤子、钉子、探针、黑猩猩）而不是抽象名词。读者记不住术语，记得住锤子。

### 五条左右

少于 4 条显得单薄；多于 6 条读者记不住，也塞不进卡片图。**卡片图的条数要和正文一致**，
不要正文 5 条、图片 3 条。

## 标签

结尾一行写 6–8 个，覆盖三个层次：

1. **主题词**（内容本身）：`#意会认知` `#波兰尼`
2. **类目词**（读者会搜的）：`#读书笔记` `#好书推荐` `#读书`
3. **领域词**（扩大触达）：`#科学哲学` `#知识管理` `#个人知识`

写进正文最后一行即可，CLI 会自动识别成话题并点掉联想词。**不要**再传 `--tags`，会重复。

## 常见错

- **太长**：流水账式复述内容。删掉所有"这本书还讲了……"。
- **太短**：只给观点不给用法，读者收藏了也不会用。
- **和自己无关**：通篇介绍内容，没有一句落到读者身上。⑦ 就是治这个的。
- **编造**：页码、引文、数据必须有据。二手来源要标明"据记载""未逐条核对"。
  不确定就删掉那条，不要含糊过去。
