# 卡片图

## 为什么是 1080×1440

3:4 是小红书信息流的原生比例。**更关键的是：手机里这张图基本按屏宽整幅显示**，
所以卡片里 1px 的字，到读者眼里就是 `1 × (屏宽/画布宽)`。

**字号要按"占画布宽的比例"来判断，不是按绝对 px。** 1080 宽画布里的 24px，
和 1280 宽画布里的 28px，读者看到的一样大——因为图都被缩放到屏宽。
下面这套下限因此用"相当于 1080 宽下的多少 px"来表达。

`render_cards.py` 就是按这个规则判的：拿每张卡自己的画布宽做归一化，
所以同一套阈值可以同时管 3:4 卡片和横版长图。

## 字号下限（硬约束）

以「相当于 1080 宽画布」计，正文区低于这些值就是不合格：

| 角色 | 下限 | 实测可用值 |
| --- | --- | --- |
| 大标题 h1 | 70px | 74–88 |
| 小节标题 / 条目名 | 30px | 33–38 |
| 正文、条目说明 | 24px | 24–28 |
| 序号 / 大字强调 | 34px | 34–50 |

**例外是元信息**：眉标（kicker）、页脚、栏目标签可以小到 17–18px——它们是装饰性的，
不承载读者必须读到的信息。

**不要用缩放绕过这条规则。** 画布放大 2 倍、字号也放大 2 倍，读者看到的完全一样；
反过来，把一个为大屏或打印设计的密排页面直接当图片发出去，字号比例会低到读不了。

### 教训：印刷版式的长图不能直接发

用 `scandinavian-style` 的密集 one-pager 模板做的「全图」卡片，正文是 8.8–12px @1280 宽，
归一化后只相当于 1080 宽下的 **7.4px**——在手机上是灰块。

它不是做错了，它是**为屏幕阅读和打印设计的**，本来就不该塞进信息流。
要发「全图」就在 1080 宽画布上按上面的下限重排；排不下就拆两张，或者干脆不要这张。
`render_cards.py` 会把这类页面直接判为不通过。

一个真实的教训：某版卡片因为渲染辅助函数只传了公共 CSS、把每张卡自己的样式表丢掉了，
全部内容以浏览器默认 **16px** 渲染。排版框架（分割线、序号、引言块）一起消失，视觉上
只是"字有点小、有点挤"，肉眼完全看不出是 CSS 没生效。**只有测量能发现它。**

## 高度预算

卡高 1440，上下内边距各 76。页脚是绝对定位，**不占文档流**——所以内容溢出时不会撑高卡片，
而是直接压到页脚上，被 `overflow:hidden` 盖掉，看起来只是"底部有点挤"。

算高度时按这个顺序累计，留 80px 余量：

```
眉标+分割线 ≈ 45   栏目标签 ≈ 65   大标题(行数 × 字号 × 1.24)
每行条目 ≈ 上下 padding + 标题 + 说明行数 × 行高
```

**先算再写，不要写完再挤。** 放不下时的处理顺序是：① 精简文字 ② 减条目 ③ 收 padding，
**不是缩字号**——缩字号正是要避免的那个错误。

## 卡片类型

一套 5 张就够，顺序即阅读顺序（6、7 是按内容加的可选张）：

| # | 类型 | 作用 |
| --- | --- | --- |
| 1 | 封面 | 一句话冲突 + 主体图。信息流里的缩略图就是它，最重要 |
| 2 | 全图 | 可选。**必须按移动端字号重排**，不能直接放印刷版 one-pager（见上） |
| 3 | 机制 | 2–4 条核心原理，带出处 |
| 4 | 地图 | 上游/下游、来路去路——给"这东西从哪来" |
| 5 | 清单 | N 条能带走的点 + 使用建议 |
| 6 | 原句 | 可选。原文 + 译文对照（`.orig`），文学／诗歌类专用 |
| 7 | 荣耀 | 可选。作者拿过大奖时单独一张；必须同时写清"奖是给全部作品的，不是给这一本的" |

## 封面主体素材：真实封面优先（实拍照片或电子封面都行）

封面是**唯一一张所有人都会看到的图**——在信息流里它缩到巴掌大，读者在半秒内决定停不停。
它的主体图不是装饰，是**识别锚点**：读者要能一眼认出"这是我见过／想买／值得读的那本书"。

### 选材规则

1. **主体图必须是这本书真实存在的封面**，两种都算：
   - **实体书照片**——自己拍的封面照、书桌上的书、带书脊的实拍；
   - **电子封面**——出版社设计的那张封面图本身。
   判据只有一句话：**读者认不认得出这是哪本书。**
2. **不算封面的**（这条是硬线）：自己拿书名／作者名排出来的**合成图**、
   星空地球剪影这类**意象图**、没有封面图的"书籍信息卡"。
   那些是我们自己做的海报，不是这本书的封面——读者认不出、搜不到，
   也拿不到"这本书真的存在"这个信号。
3. **电子封面的额外要求：原图要干净。** 带水印、店铺 logo、促销角标
   （"包邮／正版／满减"）、评分星条的一律不能用；裁不掉就换一张。
   常见的电商商品图就是这个毛病，别直接用。
3b. **从电子书文件里取封面时，先验一眼再用。** "书里自带的"不等于合格：
   有些 EPUB 的 `cover.jpg` 是**合成图**（拿同一系列的底色压上本书标题），
   有的还带"系列销量 XX 万"这类角标。看见 **①标题是后来压上去的**、
   **②带销量／促销角标** 任何一条，就当它不存在，走外部找图。
   （2026-10-07《埃隆之书》实测：`OEBPS/image/cover.jpg` 是《纳瓦尔宝典》的红底
   压上本书书名＋序作者名＋销量角标，两条都踩。）
4. **中文版优先。** 同一本书有中文版，就用中文版封面：读者能对上、搜得到、买得着。
   只有外文版时，用**外文版封面**，并在页脚写清版本。
5. **缩略图尺度下要认得出来。** 书名和作者在巴掌大时还看得清；拍歪、反光、过暗、
   手指挡住关键位置的，重拍或换一张。
6. **和版式共处。** 书的颜色会成为封面的第二主色。暖纸底配一本冷蓝／墨绿很稳；
   高饱和荧光色的书会和强调橙打架，这时要么压饱和度，要么改成书脊＋局部特写。
7. **封面不承担"讲内容"的任务。** 认出书 + 停下滑动就够了，讲内容交给标题和后面的卡。

### 实拍和电子封面怎么选

**手边有实物就自己拍**——带手指、灯光、桌面痕迹的照片读起来是"某个人在读这本书"，
最难被当成广告，这是读书类账号最便宜的信任来源。

**没有实物时就用电子封面**，但要靠版式把它做"软"，别做成电商列表里的白底商品图：
铺在暖纸底上、压一点饱和度、加一层柔和阴影，让它像"书放在纸上"而不是"商品挂在货架上"。
中文读者对"这是不是一张商品图"很敏感——同样的封面图，处理和不处理是两种观感。

读书账号卖的不是书，是**读的人**；所以能用实拍就用实拍，但不能为了实拍去用一张
认不出是哪本书的图。

### 都拿不到时

按顺序退：① 请用户拍一张；② 找这本书真封面的电子版（中文版优先、无水印）；
③ 都没有，用外文版封面，并在确认时**明说**"只有外文版封面，没有中文版"。

**不要**用星空、地球、剪影这类"意象图"，或自己合成的书名图顶替书封——
它们不承担识别功能，读者认不出这是哪本书。

### 处理封面图

**电子封面：不用透视校正。** 只要 ① 转成 RGB PNG（不要 CMYK、不要带 alpha 的怪色）；
② **宽度 ≥1600px 最好**；③ 确认没有水印／锐化噪点。处理完同样**贴给用户看一眼**再排版。

**尺寸的硬下限按"交付那一版的画布"算，不是按渲染画布算。** 封面图在卡片里固定画到
566px 宽（1080 画布），所以导出 `jpg_width: 1440` 的那一版里，它实际只被画到
**≈755px**——**源图 ≥900px 就够锐**，≥1600 是留余量。低于 1080 不代表一定换：
先看交付版里它被画多大。（2026-10-07《埃隆之书》只有 970×1500 的英文原版封面可拿，
按这条判定可用；889px 的封面此前也通过过。）

**手机实拍：** 封面几乎一定带倾斜、透视、手指和杂乱背景。用
[`scripts/prep_cover.py`](../scripts/prep_cover.py) 两步处理：

```bash
# 1) 叠坐标网格，读出书四角的像素坐标（别靠猜）
python3 <skill>/scripts/prep_cover.py grid ~/照片.jpg --out /tmp/grid.png

# 2) 透视校正 + 裁边 + 压色 + 混纸色
python3 <skill>/scripts/prep_cover.py flat ~/照片.jpg \
  --corners 28,52,703,22,742,1010,40,1016 \
  --out <post-dir>/assets/cover.png
```

四角顺序是 **左上、右上、右下、左下**。处理完**把图贴给用户看一眼**再排版——
"这张照片能不能用"是审美判断，脚本定不了。

## 封面改造：书封原版展示，主题装饰画在四周

默认封面是"纸底 + 书封"。要更像一本会被点开的笔记，就在**书封四周**再加一层主题插画——
书封本身保持原版（不加工、不裁切、不叠滤镜），装饰全部画在它左右两栏里。装饰是**矢量**的：
勾线在前、平涂在后、颜色收着，这就是 `illustration-style` 的风格指纹落到 SVG 上的写法，
也是它不用跑图模型、能复现、缩到任何尺寸都锐的原因。

```bash
python3 <skill>/scripts/cover_deco.py --list                     # garland / notes
python3 <skill>/scripts/cover_deco.py --preset garland > /tmp/deco.svg
```

把输出的那一段整段贴进 [`assets/cover.html`](../assets/cover.html) 里的 `<svg class="deco">`
（模板里已经是 `garland` 那一版，直接改）。版式在 `card.css` 的「封面的主题插画装饰层」
一节：`.stage`（845 高、左右出血）→ `.deco`（线稿）→ `.book`（书封，z-index 最高）。

**主题从书里来，不要泛泛地"加点花"。** 拆出 2–3 个能画成图形的东西就够了——
《The Beauty of the Husband》拆的是「29 首探戈 → 音符」「美与伤口 → 玫瑰与刺」
「画布本身的龟裂 → 裂纹」。换书就换这几个 motif 和坐标。

### 三条硬规矩

1. **书封必须原版完整。** 装饰永远画在书封矩形**之外**（脚本里 `BOOK_L` / `BOOK_R` 两侧的栏）；
   书封交给 `.book img`，不加工、不叠色、不裁切。"周围丰富"和"封面原版"是两件事，
   别为了构图去压封面。
2. **花叶必须完整落在画面内**，不能被画布边缘切一半（只有藤蔓末端允许出画）。脚本里
   `leaf()` / `bud()` 的收缩循环负责这件事；改了坐标先渲染一眼再信。
3. **强调色只做信号。** 装饰里 `--accent`（#FD6408）最多一两处小花小苞，大面积铺色走
   `--deco-terra / olive / gold / rose`，跟着书封自身的色调走。

书封为了给装饰让位要从 566px 收到 500px，卡片其余部分（眉标／标题／页脚）不动。
改完两个脚本都要过：`render_cards.py`（溢出／压页脚／字号）和 `check_content.py`
（强调色／封面素材）。

## 起步方式

把 [`assets/card.css`](../assets/card.css) 复制到放 HTML 的目录里，再从
[`assets/cover.html`](../assets/cover.html)（封面）和 [`assets/card.html`](../assets/card.html)
（内容卡，编号条目与紧凑列表两种区块任选）改内容。

**CSS 必须和 HTML 同目录**，用相对路径引用。渲染器测量时会生成一个同目录的临时副本；
相对路径断了的话量到的是没有样式的页面（整版 16px），会被误读成"设计太差"。

## 版式约定

所有卡片共用一套 chrome：顶部左右眉标 → 1px 分割线 → 栏目标签 → 大标题 → 内容区 → 底部页脚。
分割线只做**分区**，不做装饰。中文标题用衬线（`Songti SC`），正文用系统无衬线。

内容区就从 [`assets/card.css`](../assets/card.css) 里这几个块里挑，别自己另起一套：
`.rows`（带编号的条目，每条=主张+例子+出处）、`.list`（紧凑条目，带一句「所以怎么用」）、
`.orig`（**原句对照**：出处 → 原文 → 译文，见下）、`.quote`（整段引文）、`.box`（一块提醒/折扣）。
`.orig .src` 是元信息（出处标签），卡片的 `metadata_selectors` 里要带上它，
否则渲染器会把它按正文的下限来量。

**原句对照（`.orig`）**：一本文学/诗歌类书值得单独给一张卡——把原文和译文并排抄下来，
比转述更有说服力，也最容易被收藏。一段三句就够，多了变成摘抄本：

```html
<div class="orig">
  <div class="q">
    <div class="src">TANGO I &middot; 伤口的光</div>       <!-- 出处，19px，算元信息 -->
    <div class="en">A wound gives off its own light, surgeons say. …</div>  <!-- 原文，衬线 26px -->
    <div class="zh">伤口自己会发光，外科医生说。……</div>          <!-- 译文，24px -->
  </div>
</div>
```

出处行只写「第几首/第几章 + 一句话主题」，不要把整段原文的来源注脚抄进卡片。
译文按人设走——平视、不用书面腔；原文里的斜体、引号照原样保留（那是作者的重音）。

配色用 [`assets/card.css`](../assets/card.css) 里的一套即可：暖纸底 + 深墨字 + **安全橙 / 金**
两个强调色。强调色**只做信号**（序号、关键词、引用块边线），不铺面积。
换配色就改那 6 个变量，不要散着改。

**强调色一号必须是 Volvo Safety Orange `#FD6408`，不要用绿色。** 这是硬规定：
高亮字（封面强调词、`→` 行动行、引用块与小节的加粗标题）一律走 `--accent`，
它们的淡底走 `--accent-wash`（`rgba(253,100,8,.06)`）——换配色时先改这两个。
色值出处是 `volvo-cars-powerpoint` skill 的 accent4。

⚠️ **Safety Orange 在暖纸底 `#F3EEE5` 上只有约 2.6:1 的对比度**，够不上大字号的
3:1 门槛。所以橙色只点**短句和关键词**（`→` 那一行、小节标题），成段正文一律退回
`--ink2`——现在的版式就是这么分的，改版式时别破坏它。

## 素材处理

手机原图（HEIC）常有 EXIF 旋转。**先转 PNG 再确认方向**，不要直接
`Image.open().rotate()` 猜角度——`ImageOps.exif_transpose()` 能按 EXIF 自动纠正。

原图通常需要压一下才和版式协调：降饱和（~0.55）、微提对比和亮度、再往纸色混合 10–15%，
裁掉四周杂乱边缘。做完在缩略图尺寸下看一眼再定。

## 渲染与实测

### 写完先按长度自查，省一轮渲染

孤字换行**没有捷径**（下面「别用静态脚本预判」那段解释了为什么），但有一个能少绕一圈的
经验窗口：**两行的段落，末行要占到列宽 40% 以上（约 14–16 字）**，否则
`render_cards.py` 会报孤字。按各区块的列宽换算，两行段落的**安全长度**是：

| 区块 | 列宽 | 字号 | 每行约 | 两行安全长度 |
| --- | --- | --- | --- | --- |
| `.rd`（`.row` 内） | 820 | 25 | 32 字 | **50–62 字** |
| `.td` / `.use`（`.item` 内） | 838 | 24 | 34 字 | **52–66 字** |
| `.box p` | 848 | 24 | 35 字 | **54–68 字** |
| `.quote i` | 840 | 27 | 31 字 | **48–60 字** |

要么写进这个窗口，要么干脆压到**一行以内**（≤ 每行字数）。落在窗口下面一点
（比如 45 字）最危险——刚好两行，末行只有十来个字。

**别用静态脚本预判。** 2026-10-06 写过一个纯字符宽度模型（`check_widows.py`，
量过就删了）：对已发布的 10 篇 50 张卡，它报出 18 处而 `render_cards.py` 只认 4 处
——**精度 18%**。根因是中文的**禁则处理**：`。`「，」「——」不能出现在行首，
浏览器会因此前后挪动断行点，字符宽度模型复现不了。所以**判定只能靠渲染器**，
上面那张表的作用是让你写的时候就落在安全区，而不是替渲染器下结论。

```bash
python3 <skill>/scripts/render_cards.py <post-dir>
```

读 `<post-dir>/manifest.json`：

```json
{
  "width": 1080, "height": 1440, "dsf": 2,
  "min_font": 20, "target_font": 24, "jpg_width": 1440,
  "background": "F3EEE5",
  "root": ".card",
  "metadata_selectors": [".top", ".foot", ".rlab"],
  "cards": [
    {"html": "build/cover.html",  "out": "01-封面"},
    {"html": "build/points.html", "out": "03-核心机制"},
    {"html": "build/wide.html",   "out": "02-全图", "width": 1280, "height": 720}
  ]
}
```

每张卡可以覆盖 `width` / `height` / `dsf` / `background` / `root` / `min_font`。
`min_font`、`target_font` 是「1080 宽下的等效 px」，渲染器按每张卡自己的画布宽换算。

它用 Chrome headless 渲染每张卡（`--force-device-scale-factor=2`，输出 2160×2880），
然后**在真实布局上测量**：

| 检查 | 判据 |
| --- | --- |
| 溢出 | `scrollHeight > clientHeight` 即失败 |
| 压页脚 | 最后一个非绝对定位子元素的底部 > 页脚顶边即失败 |
| 字号 | 正文区（排除 `metadata_selectors`）出现低于下限的文本即失败，按画布宽归一化 |
| 孤字换行 | 折行块最后一行填充率 < 40% 即警告 |

退出码非 0 表示有不通过项。**每一轮改版都要重跑**；`--dsf 1` 可以快速试版。

孤字换行是警告不是错误——它是"这段该改了"的信号，通常删两个字就能解决。
