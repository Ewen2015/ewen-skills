# 卡片：字段口径与写法

一张卡 = 一本书的**可检索入口**（frontmatter）+ **可引用的内容**（正文）。
目标是让模型读完这一张就能带着出处回答问题，不必去翻原笔记。

## frontmatter

```yaml
---
slug: naval-almanack          # 必填，与文件名一致
title: 纳瓦尔宝典：财富与幸福指南   # 必填，中文书名
original_title: The Almanack of Naval Ravikant
author: 纳瓦尔·拉维坎特          # 必填，**思想的来源**，不是编者的名字
author_en: Naval Ravikant
editor: 埃里克·乔根森（Eric Jorgenson）   # 没有就留空，别删字段
translator: 赵灿
publisher: 中信出版社
year: 2022
edition_note: 中文版 2022-04，ISBN 978-7-5217-4112-4；英文原著 2020
source_type: 二手汇编          # 必填：一手 / 二手汇编 / 一手（署名作者）…
source_warning: 全书由推文／播客／访谈整理……   # source_type 不是"一手"时必填
read_at: 2026-10-05           # 必填，读完的日期
notes: notes/naval-almanack.md # 原笔记路径，相对 skill 目录（缺失只提醒）
domains: [财富, 幸福, 判断力]    # 必填，宽泛的领域词
thesis: 财富是睡觉时仍在为你赚钱的资产……  # 必填，一句话立场
triggers: [用时间换钱, 时薪, 要不要创业]   # 必填，检索入口
confidence: 中——概念清晰，但整体是二手汇编
aliases: [纳瓦尔, Naval]       # 别名/外文名/俗称
---
```

**`author` 与 `editor` 必须分开。** 说"纳瓦尔说"和"乔根森编的书里写"是两件事，
引用时出错就出在这里。

## triggers 是检索接口，最重要

它不是关键词表，是**用户会说的话**。写法：

- **写口语，不写章节标题。** ✅`辞职` `做自己的产品` `加班换钱` ❌`创业与股权`
- **把同义说法都写上。** `辞职` / `离职` / `要不要创业` / `单干` / `副业` 各写一条。
  中文没有词形变化，换一个词就是一次完全不同的检索。
- **5–30 条。** 少于 5 条检索会漏；超过 30 条时后面的基本不会被问到。
- **顺序有意义**：index 只印前 16 条，把最可能被问到的放前面，长尾放后面。
- **一条不要太长。** 长句只在问题原样复述时才命中，实用价值低。

`domains` 和 `triggers` 的分工：`domains` 是宽泛领域（命中权重低，只在问题明确谈到
这个领域时才加分），`triggers` 是具体问法（权重高）。别把具体问法写进 domains。

## thesis

一句话，**可反驳**的那种。检验标准：能不能想象一个理性的人反对它。

- ✅ `财富是睡觉时仍在为你赚钱的资产；出租时间不可能致富。`
- ❌ `一本关于财富和幸福的好书。`（不可反驳，等于没说）

## 正文六节

| 节 | 写什么 | 从原笔记哪里来 |
| --- | --- | --- |
| `什么时候该想起它` | 3–5 条**问题形态**，写成"用户在问什么" | 关键词表 + 主旨 |
| `什么时候别用它` | 边界、失效场景、代价。**必须有** | 「未解决之处」+「评论」 |
| `核心命题` | 2–5 条：主张 + 依据 + 出处，要可反驳 | 「关键主旨」+「论证结构」 |
| `常被引用的原句` | 加引号带位置，4–6 条 | 「关键主旨」的原句 |
| `与其他书` | 上游／同体例／**对撞**，只写有依据的 | 「上游／下游」「隐身人表」 |
| （可选）`我的判断` | 与作者观点分开标 | 「评论」 |

**`什么时候别用它` 是必需的，不是可选。** 没有它，第二大脑会退化成"什么问题都能往上套"
的引经据典机器——那是最糟的形态。

## 从 read-a-book 笔记提炼

`read-a-book` 的输出结构是固定的（外·脉络／内·正文／评·判断），可以直接映射：

```bash
python3 scripts/brain.py add --notes <某本书的 notes.md 路径> --slug <slug>
```

脚本会把原笔记复制进 `notes/<slug>.md`，把机械的部分填好（书名、书目行、一句话主旨、
关键词表、未解决之处），并在末尾留一段「待处理」原料。笔记来源不限——`read-a-book`
的产物最省事，因为它的章节结构是固定的；别的来源也能用，手工填的会多一些。然后：

1. 按上面的表填六节正文——**这一步是判断，脚本做不了**；
2. `domains` / `triggers` 主要从「关键词表」和「未解决之处」来，但要用口语重写；
3. 删掉末尾「待处理」整段；
4. `python3 scripts/brain.py index && python3 scripts/brain.py check`。

## 反模式

- **把卡片写成读书笔记的压缩版**——卡不是摘要，是**为了回答而组织的**。
  摘要按书的顺序，卡片按问题的顺序。
- **只写金句不写边界**——金句谁都能引，边界才是这个 skill 的价值。
- **triggers 抄章节标题**——那样只有背过目录的人才搜得到。
- **`source_type` 全填"一手"**——汇编、转述、访谈整理都是二手，如实写。
