# 文案：标题与正文

> **先读 [`persona.md`](persona.md)。** 这份文件讲的是"怎么写才成立"（字数、标签、重音、
> 半成品标记），`persona.md` 讲的是"这个号该怎么说话"（语气、开头、结尾、出处行、
> 反面清单）。两份都要满足；冲突时以 `persona.md` 为准。
>
> **去 AI 味 + 贴人设的通用手法在 [`../../human-writing/SKILL.md`](../../human-writing/SKILL.md)**
> ——那里管"像不像一个人在说这个人设的话"（声音指纹、AI 味清单、写完出声念）；
> 本文件只管小红书这一层的平台约束（字数、标签、重音手法、骨架、半成品标记）。

小红书是**信息流**：读者在滑动中决定停不停。所以文案的任务不是"介绍这份内容"，
而是**在前两行让人认出"这说的是我"**。

## 标题

硬限制 **20 字**，超了 CLI 直接抛错。宁短勿长，13–17 字最好念。

有效的是**认知冲突**，不是概括：

| 套路 | 例 |
| --- | --- |
| 你懂的比你能说的多 | 为什么你懂的，永远比能说出来的多 |
| 反常识结论 | 越努力越没结果，因为你搞反了顺序 |
| 具体到能想象 | 我用 3 年才明白：说不清的本事最值钱 |
| 指名对象 + 好处 | 想做知识管理，先读这一本 |

**不要**用：震惊体、纯书名、"XX 读后感"、"分享一本好书"——这些没有信息量，
也不会让人想点开。

标题和封面图是同一句话的两半：**封面承担冲击力，标题承担信息**。两者不要重复措辞，
但必须指向同一个点（曾经出现过封面写"永远比说出来的多"、标题写"永远比能说出来的多"
这种不一致，是编辑事故，发布前一定要对齐）。

## 正文骨架

目标 **700–900 字**。低于 600 字读者觉得"没什么可收藏的"；超过 1000 字会被截断。

```
① 钩子（2–3 行）    一个读者正在经历的具体场景，不要抽象概括
② 概念（2–3 行）    给出名字 + 一句话定义 + 出处（页码/年份）
③ 事实底座（1–2 行）体量、结构、重心——让读者知道这是什么量级的东西
④ 可带走的点（主体）N 条，每条 = 一句观点 + 一句"所以你该怎么做"
⑤ 怎么用（2–3 行）  怎么读/怎么练/从哪开始，越具体越好
⑥ 顺藤摸瓜（2–4 行）相关作品，一句话说明关系
⑦ 收尾（1–2 行）    回到读者自己身上：这跟你有什么关系
⑧ 出处（1 行）      作者《书名》｜编者/译者｜版本
⑨ 标签（1 行）      #标签 #标签 ...
```

### ④ 是最重要的一段

读者点赞收藏的动机是"**我以后用得上**"。所以每条必须从内容里翻译成读者能用的一句话：

> ✗ 附带焦点：细节退到背景，整体才会浮现。
> ✓ 附带→焦点：用锤子时，手感在手上，注意力却钉在钉子上。细节必须退到背景，整体才会浮现。
>   → 别一边做一边解剖自己，先做进去。

用**具体的物**（锤子、钉子、探针、黑猩猩）而不是抽象名词。读者记不住术语，记得住锤子。

### 五条左右

少于 4 条显得单薄；多于 6 条读者记不住，也塞不进卡片图。**卡片图的条数要和正文一致**，
不要正文 5 条、图片 3 条。

## 标签

结尾一行写 6–8 个，覆盖三个层次：

1. **主题词**（内容本身）：`#意会认知` `#波兰尼`
2. **类目词**（读者会搜的）：`#读书笔记` `#好书推荐` `#读书`
3. **领域词**（扩大触达）：`#科学哲学` `#知识管理` `#个人知识`

写进正文最后一行即可，CLI 会自动识别成话题并点掉联想词。**不要**再传 `--tags`，会重复。

## 常见错

- **太长**：流水账式复述内容。删掉所有"这本书还讲了……"。
- **太短**：只给观点不给用法，读者收藏了也不会用。
- **和自己无关**：通篇介绍内容，没有一句落到读者身上。⑦ 就是治这个的。
- **编造**：页码、引文、数据必须有据。二手来源要标明出处，不要含糊过去。
- **交半成品**：正文或卡片里出现"待核实""需查证"这类字眼——见下一节，这是硬禁止。

## 成品里不许出现「半成品标记」

面向读者的成品——**标题、正文、每一张卡片上的每一个字**——不允许出现：

> 待核实 · 需查证 · 待考 · 据称 · 据传 · 未经核对 · 不确定 · 存疑 ·
> 「本次未找到……」（当作结论用时）· 各种"(?)"

它们在内层笔记里**是对的**：`read-a-book` 要求把不确定标出来，`second-brain` 宁可不引也不硬套。
**但那是证据分层，不是给读者看的。** 读者看到"需查证"只得到两个信息：你也不确定，而且你没去查。

碰上一个不确定的点，**只有三条路，没有第四条**：

1. **能核实就现在核实。** 查原书、查一手来源，核完把事实写实，不留标记。
   例："偏转困境是萨根等人提出的" ← 书末参考文献里就有那篇 *The Deflection Dilemma*，可查。
2. **核不了，就把断言收缩到你能负责的范围。** 把"X 影响了 Y"改成"萨根提出 X"、
   把"公认"改成"这本书里说"。范围一收，它就不再需要"需查证"。
3. **这条不重要，就整条删掉。** 宁可少一条，不要交半成品。

**判据（写完自己念一遍）**：这句话给一个不认识这本书的读者看，他会读成"结论"，
还是"作者在给自己留后路"？后一种就是半成品。

**注意区分两类标记**，不要连好的也删掉：
- ✅ **出处标记**——`正文自述` `参考文献` `第 3 章` `p.xi`：告诉读者这话从哪来，是可信度。
- ❌ **不确定标记**——`需查证` `待核实` `据称`：告诉读者你自己没底，是半成品。

### 发布前机械自检

在摆给用户确认之前，先跑一遍，**必须全过（退出码 0）**：

```bash
python3 <skill>/scripts/check_content.py <post-dir>
```

它一次查五件事，正文和卡片 HTML 一起查：① 半成品标记（上表那串词）；② 正文里的
`**加粗**`；③ 强调色是不是 `#FD6408`；④ 封面素材存在、是 RGB、宽度够；⑤ 只留了一个
标题／正文版本。**别靠记性手敲 grep**——脚本会漏词、你会漏跑，规则写进脚本才不退化。
`rednote-assistant` 的 `plan.py ready` 已经把它并进发布就绪闸门，跑那个就够了。

其中「人设：无 AI 味词」那一项的词表**不在本文件里**——它来自 `human-writing`
（`human_check.py` 的通用词表 + `persona.md` 的「禁忌词」行）。要在**写作阶段**就拦，
照 [`../../human-writing/SKILL.md`](../../human-writing/SKILL.md) 第 3 步跑一次
`human_check.py --strict`（软信号——比如每条观点都配一句 `→ 怎么用`——也判失败）。

## 正文没有加粗——重音只能用这三招

**小红书图文笔记的正文不支持任何富文本。** 网页编辑器的 ProseMirror schema 里只有一个
`errorMark`，没有 `bold`／`italic`：`document.execCommand('bold')` 返回 true 但不产生
任何 `<strong>`，从 Word／公众号复制带格式的文本也会被清掉，实测输入 `**字**` 会原样
显示成 `**字**`（不渲染）。长文模式也没有加粗，只有小标题和引用格式（据凤凰网评测）。
所以"把重点加粗"这种需求**在正文里做不到**，先跟用户讲清楚，不要空试 markdown。

能用的重音手段只有三种：

1. **emoji 领起段落**——每个关键段落开头放一个语义相关的 emoji（😰 起、📚 书、🔍 查、
   🎯 结论、🧭 出处）。最容易见效，也给大段文字一个视觉锚点。
2. **核心句单独成行 + 段落间空行**——重点句自己站一行，不埋在人堆里。
3. **符号前缀**——`▍` 标核心论断、`👉` 标行动项。两个符号各管一件事，别混用也不要滥用。

注意 emoji 和符号**都占字数**，而且平台计数里 emoji 通常按 2 个字算。加完必须重新读数：
计数器是页面上的 `.editor-length-wrapper`，`fill`／`verify` 之后顺手核一眼，别等发布时
才发现超 1000。
