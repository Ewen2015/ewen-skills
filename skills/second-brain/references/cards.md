# 卡片：字段口径与写法

一张卡 = 一本书的**可检索入口**（frontmatter）+ **可引用的内容**（正文）。
目标是让模型读完这一张就能带着出处回答问题，不必去翻原笔记。

## frontmatter

```yaml
---
slug: naval-almanack          # 必填，与文件名一致
title: 纳瓦尔宝典：财富与幸福指南   # 必填，中文书名
original_title: The Almanack of Naval Ravikant
author: 纳瓦尔·拉维坎特          # 必填，**思想的来源**，不是编者的名字
author_en: Naval Ravikant
editor: 埃里克·乔根森（Eric Jorgenson）   # 没有就留空，别删字段
translator: 赵灿
publisher: 中信出版社
year: 2022
edition_note: 中文版 2022-04，ISBN 978-7-5217-4112-4；英文原著 2020
source_type: 二手汇编          # 必填：一手 / 二手汇编 / 一手（署名作者）…
source_warning: 全书由推文／播客／访谈整理……   # source_type 不是"一手"时必填
read_at: 2026-10-05           # 必填，读完的日期
notes: notes/naval-almanack.md # 原笔记路径，相对 skill 目录（缺失只提醒）
domains: [财富, 幸福, 判断力]    # 必填，宽泛的领域词
thesis: 财富是睡觉时仍在为你赚钱的资产……  # 必填，一句话立场
lens: 这笔账是财富、金钱还是地位？它有没有杠杆，能不能在你睡觉时还在长？  # 必填，作者看问题的那一句
triggers: [用时间换钱, 时薪, 要不要创业]   # 必填，检索入口
dimensions: [财富金钱地位, 杠杆, 专长与替代]  # 必填，挂到 dimensions.md 的维度上
weight: 0                     # 可选，越高越可能占 index.md 每维的代表位
confidence: 中——概念清晰，但整体是二手汇编
aliases: [纳瓦尔, Naval]       # 别名/外文名/俗称
---
```

**`author` 与 `editor` 必须分开。** 说"纳瓦尔说"和"乔根森编的书里写"是两件事，
引用时出错就出在这里。

## triggers 是检索接口，最重要

它不是关键词表，是**用户会说的话**。写法：

- **写口语，不写章节标题。** ✅`辞职` `做自己的产品` `加班换钱` ❌`创业与股权`
- **把同义说法都写上。** `辞职` / `离职` / `要不要创业` / `单干` / `副业` 各写一条。
  中文没有词形变化，换一个词就是一次完全不同的检索。
- **5–30 条。** 少于 5 条检索会漏；超过 30 条时后面的基本不会被问到。
- **顺序有意义**：index 只印前 16 条，把最可能被问到的放前面，长尾放后面。
- **一条不要太长。** 长句只在问题原样复述时才命中，实用价值低。

`domains` 和 `triggers` 的分工：`domains` 是宽泛领域（命中权重低，只在问题明确谈到
这个领域时才加分），`triggers` 是具体问法（权重高）。别把具体问法写进 domains。

## thesis

一句话，**可反驳**的那种。检验标准：能不能想象一个理性的人反对它。

- ✅ `财富是睡觉时仍在为你赚钱的资产；出租时间不可能致富。`
- ❌ `一本关于财富和幸福的好书。`（不可反驳，等于没说）

## lens：作者看问题的那一句

一句话，**这个作者拿到任何一个陌生问题时，习惯先问什么**。它是检索和回答两头共用的东西：

- 回答时，它是「这个视野能给这题加哪一维」的入口；
- 检索时，它让"该不该跳槽"这种没人写过的题，也能被某个维度接住。

- ✅ `这笔账是财富、金钱还是地位？它有没有杠杆，能不能在你睡觉时还在长？`
- ❌ `关于财富与幸福的书。`（这是内容简介，不是看问题的方向）
- ❌ 超过 60 字（压不成一句，说明还没提炼出来）

写法：先问"这位作者会怎么打量一件与他主题无关的事"，再写下来。

## dimensions：挂到路由表上

2–6 个，取自 [`dimensions.md`](dimensions.md) 的**受控词表**，不是自由发挥。

- **维度数是人为固定的（~25 个）。** 所有书共用一张表，这是 `index.md` 不随书数膨胀的原因；
  随手加维度会同时破坏检索和预算。
- **只有现有维度确实装不下这本书的视野时，才在 `dimensions.md` 里加一个**，别为了一本书的方便。
- `dimensions` 和 `domains` 不是一回事：`domains` 是学科领域（宽泛、低权重），
  `dimensions` 是思考方向（决定这本书会不会被路由到）。

## weight（可选）

整数，缺省 0。`index.md` 每维只列几本**代表书**，代表位按 `weight` 排，同 weight 按读完日期近的排。
想让某本书在某个维度稳定出镜，就给它一个正数。书多了以后这是你唯一的策展旋钮。

## confidence（可选，但强烈建议）

一句话，回答"这本书的话能信到什么程度"。`recall` 每本候选都会印出「置信：」这一行，
模型据此决定要不要给结论加限定词。写清**哪部分硬、哪部分软**：

- ✅ `中——概念清晰且可核查，但整体是二手汇编，且带幸存者偏差`
- ❌ `高`（没有信息量，等于没写）

## 「与其他书」：写的是检索边，不只是感想

这一节由 `brain.py` **零 LLM 解析成类型边**，反方臂沿着它走；`check` 也会查它。所以写法有约束：

- **受控词表**（左边是你写的，右边是脚本记的）：
  `对撞`／`对立`／`冲突`／`相反`／`反向` → 对撞；`上游`／`来源`／`承自` → 上游；
  `下游`／`衍生` → 下游；`同体例`／`同脉络`／`同向`／`呼应`／`互补`／`语境` → 同体例；
  `自查`／`软肋` → 自查。认不出类型记 `相关`；一条里一个 `《书名》` 都没有就整条丢掉。
- **优先写「对撞」，而且两边都写。** 反方臂按 对撞 → 上游/下游 → 同体例 的优先级拉书；
  只在一边写，另一边就吃不到这条边（`check` 会报"单边对撞"）。
- **书名用 `《》` 包起来，且能对上库里的书**（标题／原名／别名任一）。对不上等于没写。
- `：` 之后那半句会成为这条边的 `why`，原样出现在 `recall` 的「可当反方」里——
  写"为什么它能当反方"，别写内容简介。
- 一行只认**第一个**类型词（只看前 60 字），所以别在一行里塞两个类型。

## 正文六节

| 节 | 写什么 | 从原笔记哪里来 |
| --- | --- | --- |
| `什么时候该想起它` | 3–5 条**问题形态**，写成"用户在问什么" | 关键词表 + 主旨 |
| `什么时候别用它` | 边界、失效场景、代价。**必须有** | 「未解决之处」+「评论」 |
| `核心命题` | 2–5 条：主张 + 依据 + 出处，要可反驳 | 「关键主旨」+「论证结构」 |
| `常被引用的原句` | 加引号带位置，4–6 条 | 「关键主旨」的原句 |
| `与其他书` | 上游／同体例／**对撞**，只写有依据的；写法见上一节（会被解析成边） | 「上游／下游」「隐身人表」 |
| （可选）`我的判断` | 与作者观点分开标 | 「评论」 |

**`什么时候别用它` 是必需的，不是可选。** 没有它，第二大脑会退化成"什么问题都能往上套"
的引经据典机器——那是最糟的形态。

## 从 read-a-book 笔记提炼

`read-a-book` 的输出结构是固定的（外·脉络／内·正文／评·判断），可以直接映射：

```bash
python3 scripts/brain.py add --notes <某本书的 notes.md 路径> --slug <slug>
```

脚本会把原笔记复制进 `notes/<slug>.md`，把机械的部分填好（书名、书目行、一句话主旨、
关键词表、未解决之处），并在末尾留一段「待处理」原料。笔记来源不限——`read-a-book`
的产物最省事，因为它的章节结构是固定的；别的来源也能用，手工填的会多一些。然后：

1. 按上面的表填六节正文——**这一步是判断，脚本做不了**；
2. `domains` / `triggers` 主要从「关键词表」和「未解决之处」来，但要用口语重写；
3. 写 `lens`（作者看问题的那一句）和 `dimensions`（挂到受控词表上，见上两节）；
4. 删掉末尾「待处理」整段；
5. `python3 scripts/brain.py index && python3 scripts/brain.py check`。

## 反模式

- **把卡片写成读书笔记的压缩版**——卡不是摘要，是**为了回答而组织的**。
  摘要按书的顺序，卡片按问题的顺序。
- **只写金句不写边界**——金句谁都能引，边界才是这个 skill 的价值。
- **triggers 抄章节标题**——那样只有背过目录的人才搜得到。
- **把 dimensions 当 domains 用**——往受控词表里塞自定义维度，会同时毁掉路由和 index 的大小。
- **`source_type` 全填"一手"**——汇编、转述、访谈整理都是二手，如实写。
- **「与其他书」写成读后感**——那是检索边：只写有依据的关系、书名带 `《》`、对撞两边都写。
