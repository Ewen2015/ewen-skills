下面命令里的 `<skill>` 指本文件所在目录。按字面写 `scripts/rsi.py` 会找不到——
当前工作目录通常是用户的项目，不是 skill 目录。

## 它干什么，不干什么

**干**：度量这条链、找断点、维护改进项队列、跑一次只改一个变量的最小试验、记账。

**不干**：读书（`read-a-book`）、做图文发帖（`rednote-post`）、排期（`rednote-assistant`）、
回答问题时取用书库（`second-brain`）。它是站在这些之上的那一层，改的是**流程和工具**。

**不替用户做内容判断**：什么选题好、哪句话该留、书的评价对不对——那是用户的事。
RSI 只问"这条链的哪一段在漏水、怎么用数据证明补上了"。

## 什么时候用

- 用户问这条读书流水线**哪里可以优化**、卡在哪。
- 一段时间没管，要做**一次体检/复盘**。
- 上一轮的改进项到期了，要**对账**。
- 要决定**下一步改什么**。

不要在一次读书/发帖的过程中顺手启动它——那会把正在做的事打断。
一次 RSI 是独立的一轮，有自己的开始和结束。

## 一轮 RSI 怎么跑

**一次只动一条。** 这是全部纪律里最重要的一条；违反它，观测到的变化就不可归因。

### 1. 取证，不凭印象

```bash
python3 <skill>/scripts/rsi.py report
```

它只读不写，输出三块：闭环覆盖与断点、成品与平台对账、改进项队列。
**报告里的每个数字都要能指到文件**——指不到的，宁可说"没埋点"，不要估。

### 2. 读地图和队列

- [`references/loop-map.md`](references/loop-map.md) —— 这条链现在长什么样、断在哪。
  如果报告和地图对不上，**先改地图**：失真的地图会让后面所有判断都错。
- [`references/backlog.md`](references/backlog.md) —— 已有改进项及其状态。
- [`references/metrics.md`](references/metrics.md) —— 指标口径。要用的指标没定义就先补定义。

### 3. 选一条，并写下假设

选择规则：**证据强度 × 对北极星的影响 ÷ 成本**。
紧急的事（会立刻断更、正在丢数据）优先于好看的事（UI、版式）。

选定后必须写出一句能被打脸的话：

> 如果我改 X，那么指标 Y 会从 a 变到 b。

写不出这句，说明这条还不该做——回去补证据，或把这条划掉。

### 4. 做最小试验

- 一次只改一个变量。
- 能一天内做完，能回滚。
- 不改动正在产出的东西（别在要发的帖子上试排版）。
- 若改进项需要写代码，先跑通一次手动流程再自动化——手动都跑不通的，自动化只会把错误固化。

### 5. 记账

把结果写回 [`references/backlog.md`](references/backlog.md)：更新 `状态`、追加观测到的变化和日期。
**不记账的改进等于没做**——下个月没人知道这条被试过、结果如何。

改进落地在别的 skill 上时，在那里留下 commit；backlog 里写清落在哪个文件。

### 6. 保留或回滚

判据是**观测到的变化**，不是感觉。样本太小就如实写"样本不足，保留观察"，别硬下结论。
采纳的移到「已完成」，附日期与前后数字；无效的标 `rejected` **并保留条目**——
失败的记录同样值钱，它能防止同一件事被重复试。

## 硬规则

- **一次只动一条**，并写清假设。
- **北极星是被取用的思想密度**，不是发布量。任何只提升发布量、不提升取用率的改动都要说明理由。
- **评比率必须带样本量。** 几十阅读量下的百分比是噪声。
- **没埋点的量不许估。** 说"没埋点"比给一个编出来的数好。
- **优化项落地后必须可回滚**，且在 backlog 里留下落点。
- **别把队列当许愿单。** 每条要有证据、成本、可证伪的验收标准；没有就删。

## 产物布局

```
rsi-reading/
|-- SKILL.md
|-- references/
|   |-- loop-map.md    这条链的当前地图（实测，会随事实更新）
|   |-- metrics.md     指标定义与口径
|   `-- backlog.md     改进项队列（唯一的状态源）
`-- scripts/
    `-- rsi.py         只读观测仪：report / coverage / posts / backlog
```

`rsi.py` 默认去这两处找数据，用 `--brain` / `--workspace` / `--post-root` 覆盖：

- 书库：`~/Documents/GitHub/ewen-skills/second-brain`
- 发布：`~/Documents/rednote`（或 `$XHS_WORKSPACE`），并兜底扫 `~/Documents/*/xhs-post`

## 反模式

- **一口气改五处**，然后说不清是哪一处起了作用。
- **优化快乐的指标**：把"我这周发了 7 篇"当成进步，而不问有几张卡真的被用上。
- **没有假设就开工**：做完了也说不出算不算成功。
- **把 backlog 写成愿望清单**：越堆越长，永远不关。
- **假装有数**：拿感觉当观测值写进对账表。
