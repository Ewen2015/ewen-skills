# 改进项队列

**这是队列，不是许愿单。** 每条都要有证据、成本、可证伪的验收标准。
没有证据的条目要么补证据，要么删掉——留着会污染判断。

状态取值：`open`（待做）｜`trialing`（在试）｜`adopted`（已采纳）｜`rejected`（否掉）｜`blocked`（等外部）

每条还要标一个**维度**，因为 S4 是分支（见 [`loop-map.md`](loop-map.md)）：

- `内容` —— 笔记与卡片本身（与渠道无关）
- `呈现` —— 同一份内容在不同载体上好不好读
- `渠道` —— 分发到哪、各渠道的规则与指标
- `取用` —— 书库被检索与引用
- `回流` —— 数据从出口流回决策
- `工程` —— 路径、归档、埋点这类地基

排序依据：证据强度 × 对北极星的影响 ÷ 成本。**一次只动一条。**
**改 S4 时必须写明作用在哪一维**，否则又要把载体/渠道/呈现焊死在一起。

## R17 · 桥接依赖漂移（websockets 必须 13.1）

状态：open
记录：2026-10-05
维度：工程 · 渠道

**证据**：2026-10-05 07:49 `rednote-post` 桥接整体不可用——`xhs.py status` 报

## R18 · S1 的外部依赖要写明（登录态 + 网络路径）

状态：open
记录：2026-10-05
维度：工程

**证据**：`book-fetch` 其余部分都通了（检索、评分、封面、队列），但 2026-10-05
取 Pale Blue Dot 时两次撞墙，且报错都指向错误的地方：

1. **登录**：`download` 报 `AUTH_REQUIRED`。CLI 有自己独立的凭据存储
   （在 `~/.config/` 下的一份独立凭据文件），**和用户在 Chrome 里的登录态不共享**；
   而 Chrome 的 cookie 库在本机受系统保护，进程读不到——「我浏览器登了」这个直觉
   在这里不成立。取新书需要一次性的 CLI 登录。
2. **网络**：那条免账号的备用书源被两层问题挡住——本机 Clash 代理会让它的 TLS
   握手直接失败（`SSL_ERROR_SYSCALL`）；不走代理时，内置运行时是 Python 3.9 +
   LibreSSL 2.8.3，不支持 TLS 1.3，服务端回 `TLSV1_ALERT_PROTOCOL_VERSION`。
   换 Python 3.12（OpenSSL 3.5）并绕过代理后，裸 `requests.get` 已能拿到 200。

**假设**：S1 的失败有一半不是"书没有"，而是"前置条件没写明"。把它显式化成一次
`doctor` 式自检，比让每个会话现场考古便宜得多。

**最小试验**：给 `book-fetch` 加 `preflight` 子命令，按顺序报告并给出修复动作：
① 书源登录态；② 代理会不会打断书源握手；③ 运行时 Python 的 TLS 版本够不够。
只报告，不自动改网络配置。

**验收**：`preflight` 的输出能让人不读源码就判断"这次能不能自动取到书、不能的话卡在
哪一层"，且对上述 3 种失效各能指名道姓。

**成本**：中

## R19 · 登录成功之后，取书路径依然不通（域选择顺序反了）

状态：open
记录：2026-10-05
维度：工程

**证据**：2026-10-05 用真实账号登录成功后（`auth login` 返回 `authenticated: true`，凭据
落盘 0600），`download` / `resolve` / `info` 仍然全部失败，报 `UNEXPECTED_ERROR (SSLError)`。
开 DEBUG 追踪，失败点在内置客户端的**构造函数**：它在构造时就去 POST 凭据校验接口，而
这次请求打在了**一个不可用的镜像**上（四个候选域里只有两个能过连通性检查，被打的那个恰
是过不了的）。调用方的初始化函数是构造**之后**才 `setDomain(<可用镜像>)`——顺序反了，
"选出可用域"这一步永远来不及生效。

**为什么它值钱**：这就是 S1 一直没闭环的直接原因。`~/Downloads` 里那 4 本书全是手工下的，
不是懒，是这条路径在登录之后依然走不通。

**已验证可行的绕法**：不传凭据构造客户端（构造时因而不校验）→ 先 `setDomain(<可用镜像>)`
→ 再直接调它的凭据校验（一个名字改写的私有方法）→ `getBookDownload(id, hash)` →
`downloadUrlToPath(ddl, path)`。2026-10-05 用这条顺序取到了 Pale Blue Dot（2.21 MB，
ISBN 与著录一致）。但依赖私有方法是把脆弱性搬进我们自己的代码，不是修好了。

**假设**：该修的是上游"先选域、后构造客户端"那一处；在它修好前，`book-fetch` 需要一个
