# 读书流水线：当前状态

这是一张**实测**地图，不是设想。括号里的数字都能用 `scripts/rsi.py report` 复现。
更新方式：每次跑完体检，把与事实不符的地方改掉——地图失真，后面所有判断都会跟着错。

## 一张图

```
  S1 取得书 ─→ S2 阅读 ─→ S3 沉淀（notes + 卡片）
    ▲ 手动      read-a-book    │
    │                          │
    │                          ├─→ S4 渲染与分发   ← 分支，不是节点
    │                          │     ├─ 载体：图文卡片 / 单页 HTML / 长文 / 打印版 / 对话
    │                          │     ├─ 渠道：公开社交（小红书）· 私域 · 自用
    │                          │     └─ 呈现：版式 · 字号 · 信息密度 · 强调
    │                          │
    │                          └─→ S5 取用（second-brain recall）→ 参与思考
    │                                    │
    └── 回流 A（断）：各渠道的反馈 → 呈现与选题 ─┘
                                          │
        回流 B（断）：S5 的取用记录 → 书库取舍与笔记重点 ←┘
```

**S1→S3 是通的，S4 是一条扇出分支，S5 是另一条出口，回流 A/B 两条边都断。**

## 关键修正：S4 是分支，不是节点

小红书**不是**这条链上的一个环节，它是 S4 里的一种实现：

- **本质**：把 reading notes 渲染成某种 **UI**，再分发到某个**渠道**。
- **现在**：只跑通了「图文卡片 → 小红书（公开社交）」这一条路径。
- **可能性**：同一份素材可以同时扇出成多种 UI——
  one-pager HTML（`scandinavian-style` 已经在做）、打印版、长文、播客稿、
  以及 `second-brain` 回答里的**对话式呈现**（那也是一种 UI 与消费方式）。

所以 S4 的设计问题不是"小红书笔记怎么做"，而是三个正交的维度：

| 维度 | 取值（现状加可能） |
| --- | --- |
| 载体 | 图文卡片（已跑通）· 单页 HTML（已跑通）· 长文 · 打印版 · 音频/对话 |
| 渠道 | 公开社交：小红书（唯一在用的）· 私域（朋友/群）· 自用（笔记、日记） |
| 呈现 | 版式、字号、信息密度、封面、强调方式 |

**当前把这三层压在了一个地方**：`rednote-post` 同时承担"选内容"、"排版式"、"发小红书"。
小红书只是渠道维度的一个取值，但它的平台约束（标题 ≤ 20 字、正文 ≤ 1000 字、
最多 18 图、网页编辑器不能加粗）已经渗进了内容层。

## 两条断掉的回流边

### 回流 A：渠道反馈 → 呈现与选题（断）

`state/state.json` 里已经躺着 19 条数据，但没有一处消费它：

- `topics.md` 的选题不看数据；
- `rednote-post/references/copywriting.md` 的写法规则不看数据；
- `plan.json` 里唯一用上数据的，是 22:00 这个时段（5 篇样本）。

而且这条边**天然是分渠道的**：小红书有阅读/收藏，私域有回复，自用渠道根本没有指标。
现在把"反馈"和"小红书"绑死了——将来加渠道，这条边必须拆成按渠道各算各的。

### 回流 B：用到的卡 → 书库取舍（断）

`second-brain` 名义上是这条链的终点（"输出是下一次思考时的 skill 插入"），但它不回话：

- 没有 recall 日志 → 不知道哪些卡被读过；
- 不知道哪些卡**从没被任何问题命中过**（死卡）；
- 不知道哪些问题反复落空（书库缺口）。

代价：**书库只增不减、只凭感觉补。**

## 这条流水线的目标（写下来，别默认）

不是"每周发 7 篇小红书"。是**把读过的书变成下次思考时真正会被调用的视角**——
分发是让它被调用、并拿到反馈的手段之一，不是终点。

北极星：**被真正取用的思想密度**。
"取用"发生在所有出口上——小红书有人收藏是取用，`second-brain` 回答里被引用也是取用，
one-pager 被人读完还是取用。现在的度量只看得见第一个出口。

推论：
- 补检索日志（R2）优先于一切美化类改进——它打开的是**看不见的那个出口**。
- 任何 S4 的改进项都要标明它作用于哪个维度（载体／渠道／呈现），否则会再次把三层焊死。
