# 读书流水线：当前状态

这是一张**实测**地图，不是设想。括号里的数字都能用 `scripts/rsi.py report` 复现。
更新方式：每次跑完体检，把与事实不符的地方改掉——地图失真，后面所有判断都会跟着错。

## 一张图

```
  S1 取得书 ─→ S2 阅读 ─→ S3 沉淀 ─→ S4 转化 ─→ S5 排期发布 ─→ S6 数据回流
     ▲ 手动      read-a-book  notes+卡片   rednote-post  assistant     state.json
     │                                                                    │
     └────────── 回流 A：数据 → 选题与写法（断） ─────────────────────────┘

  S7 再取用：下次思考时 second-brain recall
     └────────── 回流 B：用到的卡 → 书库取舍与笔记重点（断）
```

**S1→S6 是通的，A 和 B 两条回流边是断的。** 所以这目前是一条"直线"，不是闭环：
内容越做越多，但没有任何信息告诉这条线"哪一段该变"。

## 两条断掉的回流边

### 回流 A：数据 → 选题与写法（断）

`state/state.json` 里已经躺着 19 条历史数据，但没有一处消费它：

- `topics.md` 的选题不看数据；
- `rednote-post/references/copywriting.md` 的写法规则不看数据；
- `plan.json` 里唯一用上数据的，是 22:00 这个时段（5 篇样本）。

代价：**能算出哪类题材有效，却仍在靠感觉选题。**

### 回流 B：用到的卡 → 书库取舍（断）

`second-brain` 是这条流水线名义上的终点（"输出是下一次思考时的 skill 插入"），但它不回话：

- 没有 recall 日志 → 不知道哪些卡被读过；
- 不知道哪些卡**从没被任何问题命中过**（死卡）；
- 不知道哪些问题反复落空（书库缺口）。

代价：**书库只增不减、只凭感觉补。** 这也让整个 RSI 失去北极星——
真正该优化的量是"被取用的思想密度"，而现在这个量根本测不到。

## 这条流水线的目标（写下来，别默认）

不是"每周发 7 篇"。是**把读过的书变成下次思考时真正会被调用的视角**。
发帖是这条链上当前唯一的外部反馈源——它提供读者数据，但它是手段，不是终点。

因此北极星候选：**被真正取用的卡片数 / 书库卡片数**。
现在测不到，所以补检索日志（R2）优先于一切美化类改进。
