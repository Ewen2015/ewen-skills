# 最佳发布时段

## 先记住两件事

**一、不能直接比阅读量。** 阅读量是累计值：去年发的笔记天然比上周发的多，
按阅读量排时段，排出来的其实是"哪篇发得早"。所以 `plan.py` 用的是
**阅读/天**，并且把发布不满 3 天的笔记整篇排除——那几天的数据还在涨，比了也没意义。

**二、样本不够就别装作用数据说话。** 每档至少 3 篇、总共至少 12 篇，
低于这个量级就明说"样本太薄"，退回下面的基线，而不是从一个样本里编出结论。

## 怎么算

`plan.py report --state ...` 按发布小时分档，每档给样本数、阅读中位数、阅读/天 中位数、
互动（点赞+收藏）中位数。用中位数不用平均数：一条爆款会把平均数拉到没有任何代表性的地方。

三种指标指向不同结论时的处理：

- **阅读/天高、互动低** → 流量来了但内容没接住，问题在内容不在时段。
- **阅读低、互动高** → 触及的人少但很准，可以考虑换时段扩量。
- 两个都一般 → 时段不是瓶颈，别在这上面过度优化。

## 基线（先验，未经本账号验证）

自有数据不够用时用这张表起步。它是通用运营经验，**不是这个账号测出来的**，
所以只能说"先发在 21:00 附近试试"，不能说"21:00 最好"。

| 时段 | 适不适合 |
| --- | --- |
| 07:00–09:00 | 通勤刷信息流，读书/知识类勉强，适合轻内容 |
| 12:00–13:00 | 午休高峰，知识类可以，竞争也大 |
| 18:00–19:30 | 下班通勤高峰 |
| **20:00–22:30** | 全平台晚高峰，读书/知识类通常吃这一段，**默认从 21:00 起** |
| 周末 10:00–12:00 | 周末上午有一波，适合长文与合集 |

一次性结论：**新手账号默认把 slot 定在 21:00**，然后靠上面那张表在攒够样本后替换掉。

## 别做的事

- 不要为了"蹭高峰"把时段排到用户自己发不出来的时间点——排期表是给自己执行的，
  不是给算法看的。用户 23:00 已经睡了，排 23:00 就只会变成定时发布兜底。
- 不要把时段调到跟已有定时笔记撞车：同一个号一天发两条会互相分流。
  `report` 会把计划外的定时笔记单独标出来，看到就先问用户要不要挪。
- 不要因为某一篇爆了就换时段：单篇是噪声，至少看 3 篇同档。
